# Реальная печатная форма задания 1С

Поддержка добавлена на основании файла **«Этап производства 431.93.1.xlsx»**.

Файл является не плоской таблицей, а печатной формой задания на производство. Поэтому используется отдельный парсер по меткам и разделам документа.

## Что распознано в тестовом файле

- Задание: `00ЦБ-431.93.1`
- Заказ: `00ЦБ-000431`
- Дата выполнения: `25.09.2026`
- Подразделение: `Производство Цех`
- Выходной артикул: `KR-01-70-241428-1256`
- План: `22 500 шт.`
- Спецификация: `KR-01-70-241428-1256 МАМА ВАРИТ КОФЕ 3 (16/2)`
- Операция: сборка изделия
- Исполнитель/машина: строка маршрута с обозначением `16/2`
- Нормативное время: `3,8 н/ч`

Из плана и нормативного времени система рассчитывает `ideal_rate_per_hour`. Для этого файла это примерно `5 921,053 шт./ч`.

## Важное правило

Значение `16/2` из печатной формы пока хранится как `route_equipment_hint`, а не автоматически превращается в код линии Coverse.

Это сделано специально: в Coverse линии имеют собственные обозначения. Связь `16/2 → конкретная линия` должна быть подтверждена через справочник/alias один раз.

## Что сохраняется в ERP staging

Кроме стандартных полей плана теперь сохраняются:

- `product_name`;
- `output_unit`;
- `route_operation`;
- `route_equipment_name`;
- `route_equipment_hint`;
- `norm_hours`;
- `ideal_rate_per_hour`;
- `route_operations` — полный список операций маршрута в JSON.

## Определение формата

Если в первых строках листа найдено выражение **«Задание на производство №»**, файл автоматически определяется как:

`1C_PRINTED_PRODUCTION_TASK`

Для обычных плоских ERP-выгрузок продолжает работать прежний табличный парсер.
