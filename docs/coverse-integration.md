# Интеграция Coverse → VITAGROUP OEE

Coverse используется как оперативный источник ответов производственных форм. По подтверждению поддержки Coverse базовый URL API: `https://app.coverse.team/api/v1`. Чтение диапазона выполняется через `GET /documents/{DOCUMENT_ID}/values/{RANGE}` с Bearer-токеном. Значения URL остаются настраиваемыми через переменные окружения.

## Особенность формы учетчика

В текущей тестовой записи значение номера талона находится в колонке B с техническим заголовком «ТАБЕЛЬНВ», а колонка J «НОМЕР ТАЛОНА» пустая. Интеграция использует J как основной источник и B как fallback. После исправления формы код менять не потребуется.

## Расчет количества склада / учетчика

Если форма дает:

- количество упаковок;
- количество в упаковке;

то нормализованное количество единиц:

`quantity = packages_qty × qty_per_package`.

Исходные поля также сохраняются внутри JSON payload.

## Почему сначала staging

Формы Coverse уже содержат факты, но часть идентификаторов еще не сопоставлена со справочниками 1С:ERP. Поэтому данные сначала пишутся в `external_event_staging`.

Это позволяет:

- не терять ни одной строки;
- защититься от дублей;
- видеть ошибки сопоставления;
- повторно обработать строки после загрузки справочников ERP;
- не создавать фиктивные номенклатуры или оборудование.

## Смена

ДЕНЬ: 09:00–21:00.  
НОЧЬ: 21:00–09:00 следующего дня.

Поля «ДАТА СМЕНЫ» трактуются как бизнес-дата смены. Поля «ДАТА» / «ТЕКУЩАЯ ДАТА» трактуются как календарная дата события. Поэтому событие в 02:00 календарного дня относится к ночной смене, начавшейся предыдущим днем.

## API VITAGROUP

- `GET /api/v1/integrations/coverse/sources` — источники и маппинг;
- `GET /api/v1/integrations/coverse/preview/{source}` — нормализованный preview;
- `POST /api/v1/integrations/coverse/sync/{source}` — загрузка в PostgreSQL staging;
- `GET /api/v1/integrations/coverse/staging/{source}` — последние загруженные строки.

## Следующий слой обработки

После загрузки справочников 1С staging будет преобразовываться:

```text
production_output → production_output_events + defect_events
qc_defects        → defect_events (reported_by = QC)
downtime          → downtime_events
warehouse         → warehouse_receipts
accountant        → контрольный производственный/учетный факт
```

## Безопасность

Токен Coverse никогда не хранится в GitHub и не передается браузеру. Он будет лежать только в `.env` на REG.Cloud. Для токена выдаются минимально необходимые права.
