# Интеграция Coverse → VITAGROUP OEE

## Цель

Coverse остается оперативным источником форм на первом этапе. Сайт VITAGROUP получает ответы форм через API, нормализует поля и сохраняет первичные события в PostgreSQL.

## Поток данных

```text
Форма Coverse
      │
      ▼
Coverse API
      │
      ▼
VITAGROUP integration adapter
      │
      ├── нормализация даты/времени
      ├── нормализация табельного номера
      ├── определение смены DAY/NIGHT
      ├── проверка обязательных полей
      └── защита от дублей
      │
      ▼
PostgreSQL
      │
      ├── production_output_events
      ├── defect_events
      ├── downtime_events
      └── warehouse_receipts
      │
      ▼
OEE / сверка / сдельная ЗП
```

## Правило смен

- DAY: 09:00–21:00;
- NIGHT: 21:00–09:00 следующего дня.

Дата ночной смены — дата ее начала в 21:00.

## Защита от дублей

Для строк Coverse формируется внешний ключ:

`document_id + sheet + source_row + response_at`

После появления стабильного row/event ID API следует использовать его вместо номера строки.

## Безопасность

API-токен Coverse:

- не хранится в GitHub;
- не передается frontend;
- хранится только как переменная окружения backend;
- должен иметь минимально необходимые права чтения таблиц и, при использовании вебхуков, управление вебхуками.

## Следующий этап

После запуска REG.Cloud:

1. создать API-токен Coverse;
2. добавить его в `.env` сервера;
3. проверить чтение всех пяти источников;
4. создать endpoint приема webhook;
5. подписать нужные таблицы на `document.updated`;
6. синхронизировать новые ответы в PostgreSQL;
7. запускать резервную периодическую синхронизацию на случай пропущенного webhook.
