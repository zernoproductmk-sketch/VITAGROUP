# Яндекс Диск как источник производственного плана

## Источник

Производственный план может находиться:

- в отдельном публично расшаренном файле Яндекс Диска;
- внутри публично расшаренной папки.

Ссылка не хранится в GitHub. На сервере она задается переменной:

`YANDEX_PLAN_PUBLIC_URL`

Если ссылка ведет на папку, путь к конкретному файлу задается отдельно:

`YANDEX_PLAN_RESOURCE_PATH`

## Как работает загрузка

Яндекс Диск предоставляет публичный REST API. Backend:

1. получает метаданные публичного ресурса;
2. запрашивает временную ссылку на скачивание;
3. скачивает файл;
4. определяет формат;
5. анализирует листы и заголовки;
6. выбирает наиболее подходящий лист;
7. нормализует строки;
8. сохраняет их в `erp_plan_staging`.

Поддерживаются:

- XLSX;
- XLSM;
- XLS;
- CSV/TXT.

## Автоопределение колонок

Система ищет известные варианты заголовков для:

- ERP_GUID;
- ID задания;
- даты;
- смены;
- цеха;
- линии / станка;
- номера заказа;
- артикула;
- клиента;
- техкарты / спецификации;
- плана в штуках;
- штук в коробе;
- коробов на паллете;
- плана в кг;
- статуса.

Для безопасного автоматического импорта желательно распознать как минимум два из трех ключевых полей:

- дата;
- номер заказа;
- артикул.

## API

`GET /api/v1/integrations/yandex-disk/status`

Показывает, настроен ли источник и когда был последний импорт.

`POST /api/v1/integrations/yandex-disk/preview`

Скачивает файл и возвращает:

- имя файла;
- размер;
- дату изменения;
- листы;
- найденную строку заголовков;
- распознанные поля;
- несколько тестовых строк.

Ничего в БД не записывает.

`POST /api/v1/integrations/yandex-disk/import`

Скачивает файл и сохраняет производственный план в staging.

## Почему сначала staging

Даже если Excel корректный, артикулы и линии нужно сопоставить с ERP/Coverse-справочниками. Поэтому импорт не создает production_runs напрямую.

```text
Яндекс Диск
    ↓
ERP plan parser
    ↓
erp_plan_staging
    ↓
reference resolution
    ↓
production_orders
    ↓
production_runs
    ↓
Coverse факт
    ↓
OEE / сверка / сдельная ЗП
```

## Безопасность

Публичная ссылка Яндекс Диска фактически дает доступ к ресурсу тому, кто ее знает. Поэтому она не коммитится в публичный репозиторий и не возвращается frontend целиком.
