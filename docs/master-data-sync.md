# Синхронизация справочников Coverse → PostgreSQL

## Источники

### Сотрудники

Источник: таблица соответствия табельных номеров.

В PostgreSQL обновляются:

- табельный номер;
- ФИО;
- должность;
- подразделение.

Ключ — табельный номер в нормализованном 5-значном формате.

### Оборудование

Источник: `СПРАВОЧНИК_ЛИНИЙ`.

В систему переносятся канонические коды линий и дополнительные варианты наименования из форм, норм и тарифов. Все варианты записываются как aliases, поэтому, например, разное написание одной линии может разрешаться в один `equipment_id`.

### Номенклатура / складской код

Источник: `Таблица соответствия складского кода и артикула`.

Сохраняются:

- артикул;
- наименование;
- складской код;
- сцепленный артикул;
- статус.

Складской код не подменяет код ERP. Для него создана отдельная таблица `product_external_codes`.

### Тарифы

Источник: `ТАРИФНАЯ_СЕТКА_2026`.

Поскольку тариф зависит не только от конкретного артикула, но и от:

- роли;
- машины;
- вида продукции;
- признака печати;
- группы тарифа;
- единицы измерения;

используется отдельная таблица `payroll_rate_rules`.

Это позволит экономисту видеть правило, по которому выбрана ставка.

### Нормы выпуска

Источник найден, но автоматический импорт **заблокирован проверкой схемы**.

Через API сейчас возвращается только один безымянный числовой столбец с величинами нормы. Без машины/вида продукции эти числа нельзя безопасно связать с OEE.

Система создаст issue `INVALID_SOURCE_SCHEMA` и не загрузит такие нормы.

## API

- `GET /api/v1/master-data/sources` — перечень справочников;
- `POST /api/v1/master-data/sync` — синхронизировать все;
- `POST /api/v1/master-data/sync/employees`;
- `POST /api/v1/master-data/sync/equipment`;
- `POST /api/v1/master-data/sync/products`;
- `POST /api/v1/master-data/sync/tariffs`;
- `POST /api/v1/master-data/sync/production_norms` — сейчас вернет BLOCKED до исправления источника.

## Полный рабочий цикл после запуска сервера

```text
1. master-data/sync
        ↓
сотрудники / линии / продукты / тарифы

2. integrations/coverse/sync/*
        ↓
external_event_staging

3. reference/resolve
        ↓
RESOLVED / PARTIAL

4. reference/promote
        ↓
рабочие факты

5. OEE + сверка + расчет сдельной ЗП
```

## Принцип

Ни одна строка справочника с неполным ключом не создает фиктивный объект молча. Ошибка или неполная строка записывается в `master_data_sync_issues`.
