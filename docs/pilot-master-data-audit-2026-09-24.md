# Пилотный аудит справочников Coverse

Дата проверки: 24.09.2026.

Документ фиксирует состояние реальных источников перед первой пилотной
загрузкой в PostgreSQL. Персональные данные сотрудников, конкретные
артикулы, складские коды и тарифные ставки в репозиторий не записываются.

## Итог

|---|---:|---:|---:|---|
| Сотрудники | 269 | 261 | 8 строк в 4 конфликтующих группах | Требует проверки дублей |
| Производственные линии | 33 | 33 | 0 | Готов |
| Номенклатура | 1041 | ориентировочно 327 | 698 неполных + 16 конфликтующих | Частично готов |
| Тарифная сетка 2026 | 47 | 47 | 0 по обязательным полям | Готов |
| Нормы выпуска | 26 | 0 из Coverse | источник содержит только один числовой столбец | Заблокирован |

Количество готовых строк номенклатуры рассчитано по текущим правилам
безопасного импорта и может измениться после исправления исходной таблицы.

## Сотрудники

В исходном справочнике:

- 269 строк данных;
- обязательные поля заполнены;
- выявлено 4 повторяющихся табельных номера;
- это не точные дубли: в 4 группах находятся 8 различающихся строк.

Правило пилота:

- конфликтующие группы не загружаются автоматически;
- остальные строки могут быть загружены;
- после исправления источника повторная синхронизация закрывает старые
  проблемы и создает только актуальные.

## Производственные линии

Выявлено 33 строки.

Проверено:

- наименование заполнено;
- статус заполнен;
- каноническое наименование заполнено;
- дублей канонического наименования не найдено.

Источник можно использовать для пилотной загрузки.

## Номенклатура

В источнике 1041 непустая строка.

Текущий безопасный ключ требует:

- наименование продукции;
- артикул;
- складской код.

По состоянию проверки:

- 343 строки содержат все три обязательных поля до проверки конфликтов;
- 698 строк не содержат полного набора обязательных полей;
- среди валидных строк найдено 9 групп повторяющегося артикула;
- все 9 групп используют разные складские коды;
- 8 групп одновременно содержат разные наименования продукции;
- 1 группа имеет одинаковое наименование и может безопасно представлять
  один товар с несколькими складскими кодами;
- конфликтующие 8 групп (16 строк) блокируются автоматически.

Правило пилота:

- неполные строки пропускаются с issue ROW_VALIDATION;
- один артикул с одинаковым наименованием и несколькими складскими кодами
  допускается;
- один артикул с разными наименованиями блокируется с
  DUPLICATE_ARTICLE_NAME_CONFLICT.

## Тарифная сетка

Выявлено 47 строк данных.

По обязательным полям не найдено пропусков:

- тип начисления;
- машина;
- единица измерения;
- ставка;
- дата начала.

Источник пригоден для пилотной синхронизации.

## Нормы выпуска

Выявлено 26 непустых строк, но данные находятся только в одном столбце E.
Заголовки, позволяющие определить машину, продукт или иной ключ нормы,
отсутствуют.

Автоматический импорт намеренно заблокирован.

До исправления исходного справочника используются:

1. норма из задания 1С/ERP, если она присутствует;
2. ручной резервный норматив в разделе «Нормативы скорости».

## Защита, реализованная перед пилотом

- Coverse читается постранично, поэтому источники больше 1000 строк не
  обрезаются;
- доступен preview источника без записи в PostgreSQL;
- конфликтующие табельные номера блокируются;
- конфликтующие артикулы блокируются;
- точные устаревшие issues закрываются при повторной синхронизации;
- история проблем сохраняется;
- реальные персональные данные и коммерческие значения не помещаются в
  GitHub.

## Порядок первой серверной загрузки

1. Открыть «Интеграции».
2. Для каждого источника нажать «Проверить источник».
3. Сначала синхронизировать линии.
4. Синхронизировать сотрудников.
5. Синхронизировать номенклатуру.
6. Синхронизировать тарифы.
7. Нормы Coverse не загружать до исправления их схемы.
8. Открыть «Пилотная загрузка справочников» и проверить фактические
   количества в PostgreSQL.
9. Исправить конфликтующие строки в исходных справочниках и повторить
   preview/sync.


## Повторная проверка реальных источников после восстановления лимита Coverse

Повторная проверка выполнена 24.09.2026 напрямую по доступным таблицам Coverse.

Подтверждено:

- лист `СПРАВОЧНИК_ЛИНИЙ` содержит отдельные поля для наименования линии, статуса и канонических соответствий;
- лист `ТАРИФНАЯ_СЕТКА_2026` содержит тип начисления, роль, машину, вид продукции, признак печати, группу тарифа, единицу измерения, ставку, вид оплаты и дату начала;
- таблица соответствия складского кода и артикула содержит наименование продукции, артикул, складской код, сцепленный артикул и статус;
- справочник сотрудников соответствует ожидаемой структуре импорта: подразделение, сотрудник, табельный номер и должность;
- лист `СПРАВОЧНИК_НОРМ_ВЫПУСКА` по-прежнему не содержит ключей, позволяющих однозначно связать числовой норматив с машиной или продукцией.

Решение для пилота остается прежним:

1. линии, сотрудники, номенклатура и тарифы допускаются к preview/sync по действующим правилам валидации;
2. нормы из Coverse не синхронизируются до исправления структуры источника;
3. для нормы используется значение из ERP/1С, если оно передано в сменном задании;
4. при отсутствии нормы ERP используется ручной резервный норматив;
5. персональные данные сотрудников, коммерческие ставки и реальные артикулы не записываются в GitHub; в репозитории хранятся только схема, код синхронизации и агрегированная статистика аудита.
