# Ручное сопоставление PARTIAL-событий

В разделе **Интеграции → Требуют сопоставления** у каждой строки есть кнопка **Сопоставить**.

## Что разрешено сопоставлять вручную

- табельный номер → сотрудник;
- код линии → оборудование;
- складской код / артикул → номенклатура;
- номер заказа → заказ ERP.

Пользователь не вводит внешний код заново: система берет его непосредственно из выбранной строки staging. Это исключает ошибку, когда соответствие сохраняется не для того кода.

## Что нельзя назначать вручную

Через этот экран не назначаются:

- `shift_id`;
- `production_run_id`.

Они должны формироваться из бизнес-даты, типа смены и производственного плана ERP. Ручное назначение этих связей могло бы исказить OEE, фактический выпуск и сдельную зарплату.

## После сохранения

1. Соответствие записывается в `external_reference_aliases`.
2. Действие записывается в `audit_log`.
3. Строка staging переводится обратно в `UNRESOLVED / PENDING`.
4. Автоматически запускается повторное разрешение связей.
5. Если все обязательные связи найдены, строка становится `RESOLVED`.
6. Все следующие строки Coverse с тем же внешним кодом используют сохраненное соответствие автоматически.

## Backend API

`POST /api/v1/reference/manual-map`

Пример тела:

```json
{
  "staging_event_id": "uuid",
  "field_name": "product_id",
  "entity_id": "uuid",
  "canonical_label": "ОВ-55-3442"
}
```

Поиск вариантов:

`GET /api/v1/reference/candidates/PRODUCT?q=1001`

Поддерживаемые типы:

- EMPLOYEE;
- EQUIPMENT;
- PRODUCT;
- PRODUCTION_ORDER.
