# Преобразование ERP staging в производственные заказы и запуски

## Что создается автоматически

Из `erp_plan_staging` система может создать / обновить:

1. `production_orders`;
2. `production_runs` — только при однозначном определении линии и смены.

## Правила безопасности

### Заказ

Заказ создается, когда определены:

- номер заказа;
- продукт.

Продукт ищется по артикулу и внешним кодам.

### Запуск

Запуск создается только если дополнительно определены:

- оборудование;
- смена.

Если печатная форма 1С не содержит смену, создается только заказ. Позже, когда приходит факт Coverse с датой/сменой и номером заказа, resolver может создать `production_run` из соответствующей строки ERP-плана.

Это позволяет не придумывать ДЕНЬ/НОЧЬ заранее.

## Норматив OEE

`ideal_rate_per_hour` переносится из ERP staging в `production_runs` как snapshot. Поэтому последующее изменение справочника нормативов не меняет уже рассчитанные исторические смены.

## Статусы ERP staging

- UNRESOLVED — еще не обработано;
- PARTIAL — не хватает справочника / линии / смены;
- ORDER_CREATED — заказ создан, запуск пока нет;
- RUN_CREATED — заказ и запуск связаны;
- ERROR — техническая ошибка.

## API

- `GET /api/v1/erp-plan/summary`
- `GET /api/v1/erp-plan/rows`
- `POST /api/v1/erp-plan/promote`

Полный цикл:

```text
Яндекс Диск
  ↓
erp_plan_staging
  ↓
promote ERP plan
  ↓
production_orders
  ↓
Coverse факт определяет смену
  ↓
production_runs
  ↓
OEE / выпуск / брак / простои / ЗП
```
