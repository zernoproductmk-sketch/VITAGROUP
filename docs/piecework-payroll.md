# Сдельная заработная плата

## Принцип

Система не выбирает спорные правила автоматически. Экономист явно задает базу выработки для расчетного периода.

Доступные варианты:

- OUTPUT — выпуск оператора;
- QC_GOOD — выпуск минус подтвержденный брак ОТК;
- WAREHOUSE — принято складом;
- ERP — факт ERP.

## Участники производства

Когда строка выпуска Coverse переводится в рабочий факт, сотрудник автоматически связывается с `production_run` через `employee_shift_assignments`.

Если у запуска один сотрудник, коэффициент участия для preview принимается равным 1.

Если сотрудников несколько, расчет блокируется до явного распределения коэффициентов. Их сумма должна быть равна 1.

## Тариф

Тариф выбирается из `payroll_rate_rules` по:

- дате;
- роли сотрудника;
- оборудованию;
- виду продукции;
- признаку печати;
- группе тарифа;
- единице измерения.

Если вид продукции / печать / группа не определены, а тарифная сетка требует этот признак, начисление не рассчитывается. Экономист подтверждает признаки артикула один раз; они сохраняются в `product_payroll_attributes`.

## Формула

`Начисление = База выработки × Ставка × Коэффициент участия`

Ставка и выбранное тарифное правило сохраняются в строке расчета, поэтому изменение тарифной сетки позднее не меняет исторический расчет.

## Статусы preview

- READY — строка готова к расчету;
- NEEDS_BASIS — не выбрана база;
- MISSING_EMPLOYEE — не определен сотрудник;
- NEEDS_ALLOCATION — несколько сотрудников, распределение не подтверждено;
- MISSING_PRODUCT_ATTRIBUTES — для выбора тарифа не хватает признаков продукции;
- MISSING_RATE — подходящего тарифа нет;
- AMBIGUOUS_RATE — найдено несколько равнозначных тарифов.

Незаверифицированный production_run является предупреждением, а не скрытой ошибкой. Такая строка после расчета сохраняется как PRELIMINARY.

## Расчетный период

Маршрут:

```text
DRAFT
  ↓
CALCULATED
  ↓
VERIFIED
  ↓
APPROVED
  ↓
EXPORTED
```

На текущем этапе реализованы DRAFT и CALCULATED. Утверждение будет добавлено вместе с авторизацией и ролями экономиста/руководителя.

- `GET /api/v1/payroll/settings`
- `GET /api/v1/payroll/preview`
- `GET /api/v1/payroll/periods`
- `POST /api/v1/payroll/periods`
- `POST /api/v1/payroll/periods/{id}/calculate`
- `GET /api/v1/payroll/rate-options`
- `POST /api/v1/payroll/products/{product_id}/attributes`
- `POST /api/v1/payroll/runs/{run_id}/allocation`
