# Правила OEE и сдельной заработной платы v1

## 1. OEE

Используем классическую структуру:

`OEE = Availability × Performance × Quality`

Все три коэффициента хранятся/показываются отдельно.

---

## 2. Availability — доступность

`Planned Production Time = плановое производственное время`

`Run Time = Planned Production Time − учитываемый незапланированный простой`

`Availability = Run Time / Planned Production Time`

Важно: заранее утвержденные перерывы и технологически исключаемое время не должны автоматически попадать в потери Availability. Это определяется классификацией причины простоя.

---

## 3. Performance — производительность

Основной вариант:

`Performance = Actual Output / Theoretical Output during Run Time`

где

`Theoretical Output = Ideal Rate per Hour × Run Time in hours`.

Пример:

- норматив: 10 000 шт/ч;
- фактическое время работы: 8 ч;
- теоретический выпуск: 80 000;
- фактический выпуск: 72 000;
- Performance = 90%.

В промышленной версии Performance выше 100% не скрываем. Это сигнал проверить норматив или источник данных.

---

## 4. Quality — качество

`Quality = Good Count / Total Count`

Для MVP:

`Good Count = Produced Count − Confirmed Defect Count`.

Контрольный вопрос на внедрении: какой брак считается подтвержденным для OEE — ОТК, согласованный оператор+ОТК или иной утвержденный показатель.

До утверждения правила система должна показывать рядом:

- брак оператора;
- брак ОТК;
- отклонение.

---

## 5. Онлайн OEE

В течение незакрытой смены OEE является предварительным.

На панели необходимо маркировать:

- ONLINE / предварительно;
- CLOSED / смена закрыта;
- VERIFIED / данные проверены.

При активном простое система должна показывать таймер от `started_at` до текущего времени.

---

## 6. Контроль расхождений

Для каждого production_run рассчитываем:

- операторский выпуск;
- подтвержденный брак оператора;
- брак ОТК;
- ГП, принятое складом;
- факт ERP.

И отклонения:

`Operator → QC`

`QC/Good Output → Warehouse`

`Warehouse → ERP`

Порог допустимого отклонения должен быть настраиваемым.

---

# 7. Сдельная зарплата

## 7.1. База

Зарплата не рассчитывается напрямую из «последнего значения формы».

Основание — подтвержденная производственная выработка за операцию/смену/запуск.

## 7.2. Формула

Базовая строка:

`Начисление = Подтвержденное количество × Тариф × Коэффициент участия`.

Для индивидуальной работы коэффициент участия обычно 1.

Для бригадной работы количество может распределяться:

- поровну;
- по времени участия;
- по утвержденному коэффициенту.

Способ распределения должен быть явно записан в данных.

## 7.3. Версионность тарифа

При изменении тарифа старые расчеты не пересчитываются по новой ставке автоматически.

В payroll_lines сохраняется ставка, действовавшая в момент расчета.

## 7.4. Статусы

Рекомендуемый маршрут:

```text
DRAFT
  ↓
CALCULATED
  ↓
VERIFIED
  ↓
APPROVED
  ↓
EXPORTED
```

До APPROVED экономист может пересчитать период.

После APPROVED изменение исходных данных должно создавать предупреждение о необходимости пересчета/разблокировки периода.

---

# 8. Что нужно утвердить до промышленного расчета ЗП

1. Какой выпуск является расчетным: оператор, склад, ERP или согласованный показатель.
2. Как распределяется бригадная выработка.
3. Уменьшает ли конкретный вид брака сдельную базу.
4. Как учитывается переналадка.
5. Есть ли минимальная гарантированная часть.
6. Есть ли коэффициенты сложности.
7. Есть ли премии за качество/OEE.
8. Какие сотрудники имеют право утверждать расчет.

Эти правила нельзя жестко «зашивать» до подтверждения экономистом и производством.
